# RationalSeed — Рациональное зерно

Локальная сатирическая визуальная новелла об Александре — человеке, который пытается решить взаимность как инженерную задачу и систематически превращает чужое «нет» в повод для следующей итерации.

Сюжет написан заново: это не сборник цитат, а самостоятельная история, собранная из характерных моделей поведения, речи, интересов и самооправданий героя.

---

## Запуск на компьютере (Linux / Windows / macOS)

Для запуска требуется установленный **Node.js 22 или новее**.

Управление проектом и запуск осуществляются через единое меню:

- **Linux / macOS:** запустите терминал в папке проекта и выполните:
  ```bash
  ./run.sh
  ```
(Если запускаете впервые, дайте права: chmod +x run.sh cli.mjs)

- **Windows:** дважды щёлкните run.bat (или запустите node cli.mjs в консоли).

В появившемся меню выберите пункт 1 («Открыть новеллу»). При первом запуске скрипт автоматически установит зависимости (npm install), соберёт проект, поднимет локальный веб-сервер и откроет новеллу в браузере по умолчанию.

## Android

Перенесите `Рациональное_зерно.apk` на телефон и установите как обычное приложение. Оно работает офлайн и не требует сервера или браузера.

Чтобы пересобрать APK после изменений, дважды щёлкните `СОБРАТЬ_APK.bat`. Новая версия появится рядом с BAT-файлом.

Сборка и публикация проверяют встроенный `build-info.json`, версию контента и адрес GitHub. Устаревший APK не будет опубликован под новым номером. Готовые установочные файлы скачивайте из [GitHub Releases](https://github.com/superhe11/RationalSeed/releases/latest), не из старых вложений чата.

## Управление

- нажмите на панель продолжения или вариант ответа;
- `1`, `2`, `3`, `4` — выбрать реплику с клавиатуры;
- `Escape` — открыть меню;
- `M` — включить или выключить фон дождя;
- прогресс хранится только на устройстве.

## Сохранения и концовки

В 1.4.1 мобильная карта стала полноэкранной: настройки скрываются по кнопке, главы выбираются в компактном списке, описание открывается поверх древа. Все главы по-прежнему на одном горизонтальном полотне. В «Обновлениях» доступны патчноуты всех выпущенных версий офлайн и отдельно указаны версия APK и версия контента.

В меню доступны автосейв и шесть ручных слотов. Перед загрузкой, перезаписью, удалением слота и новой игрой есть подтверждение. Новая игра заменяет только автосейв: ручные слоты и коллекция концовок сохраняются. Старый сейв v3 переносится автоматически. В Android основная копия хранится в системном хранилище приложения, а прежняя WebView-копия оставлена для совместимости. Удаление приложения или очистка его данных удалит прогресс.

Открытые концовки можно перечитать без изменения текущей игры. Для закрытых показаны названия и подсказки, но не финальный текст.

## Обновления внутри Android-приложения

Начиная с 1.4 обновления проверяются и скачиваются через GitHub, без аккаунта игрока. APK: [GitHub Releases](https://github.com/superhe11/RationalSeed/releases/latest). Доступность GitHub зависит от сети: отсутствие блокировки нельзя гарантировать для любого провайдера.

В 1.3 добавлено горизонтальное древо всех сцен/ответов/финалов, текущий и общий прогресс, масштаб и переходы к главам. При ошибке автоматической проверки видна диагностика, запрос повторяется при восстановлении сети и раз в минуту, пока приложение открыто и проверка не удалась. Используются два HTTP-транспорта; это не обход блокировки домена. Новый APK можно установить поверх прежнего без удаления данных.

Переход с 1.1–1.3: один раз включите VPN и получите 1.4 со старого сервера, либо установите APK 1.4 поверх прежнего, не удаляя приложение. Старый APK 1.0 не содержит загрузчик обновлений и требует установки нового APK. Старый сервер остаётся только для перехода; в 1.4 проверка к нему не обращается.

При запуске и возвращении в приложение проверяется `https://raw.githubusercontent.com/superhe11/RationalSeed/updates/latest.json`. При наличии новой версии показываются патчноут, размер и кнопка «Скачать и обновить». Загружается ZIP с HTML/CSS/JS и графикой, а не APK. Перед переключением ожидается запись сохранений. Архив проверяется по SHA-256; допускается точный URL версии в Releases этого репозитория и прежний доверенный адрес для совместимости. При неудачном запуске Capgo Updater возвращает предыдущую рабочую сборку. Телеметрия Capgo выключена; прогресс серверу не передаётся. Токен GitHub в приложение не включается.

Обновления добровольные, без интернета работает установленный контент. При следующем холодном запуске отложенная новая версия снова предлагается. Полноценный откат защищает от сбоя запуска, а не от любой логической ошибки в сценарии.

### Как выпускать следующие версии

1. Внесите изменения в сюжет, код или оформление. В app/release.json увеличьте contentCode и versionName, обновите список notes. Для правок веб-контента параметр runtimeVersion менять не нужно.

2. Запустите ./run.sh (или run.bat) и выберите пункт 2 («Подготовить обновление»). Скрипт соберёт неизменяемый OTA-архив ZIP и обновит манифесты latest.json.

3. Закоммитьте изменения в Git:
    ```Bash

    git add .
    git commit -m "Релиз v67"
    ```

4. В меню выберите пункт 3 («Опубликовать обновление в GitHub»). Скрипт отправит коммиты в ветку main, создаст релиз с ZIP-архивом на GitHub Releases и переключит манифест в ветке updates.

5. (Опционально) Если вы меняли нативные плагины или саму оболочку Android, пересоберите APK через пункт 4 и прикрепите его к релизу.

Это self-hosted режим открытого Capgo Updater, не подписка Capgo Cloud и не Expo. Пакеты обновлений доступны по ссылке без аккаунта; первичный APK можно продолжать распространять вручную.

`main` содержит исходники, `updates` — отдельный указатель актуального OTA. Не отправляйте `main` поверх `updates`: лента переключается скриптом публикации. Публикация Sites нужна только для обновления веб-версии и перехода старых клиентов, а не для обычных обновлений клиентов 1.4+.
